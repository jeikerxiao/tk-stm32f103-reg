# 实验23 DS18B20数字温度传感器实验

> 一句话概括：用一根信号线（PA1）跟 DS18B20 温度传感器"打摩斯密码"，把读到的温度显示在 LCD 上——学会单总线时序 + 微秒级延时怎么用寄存器手写出来。

## 一、实验简介

- **实验目的**（官方 `readme.txt`）：学习 DS18B20 数字温度传感器的使用。
  通俗讲：DS18B20 只有一根数据线（叫 DQ），单片机想读温度，就得靠**拉高/拉低这根线的时间长短**来传 0 和 1。
  本实验让你亲手用 GPIO 寄存器 + 微秒延时，把这套"时序协议"敲出来，而不是调库函数。
- **在学习路线中的位置**：
  - 前置：实验1（LED 输出）、实验4（串口）、实验7/8（定时器，帮你理解"计时"）、实验10/11（OLED/TFTLCD，本实验用它显示温度）。
  - 后续：**实验24 DHT11 数字温湿度传感器**——同样是单总线，时序套路几乎一样，只是"1 和 0 的判法"反过来；
    再往后是实验19 IIC、实验20 SPI，你会对比出"单总线只有一根线"到底省了什么、代价是什么。
- **开发板与芯片**：正点原子 MiniSTM32 V4 开发板，主芯片 STM32F103RC（Keil 工程里的器件即 `STM32F103RC`，
  `IRAM(0x20000000,0x0000C000)`＝48KB RAM，`IROM(0x08000000,0x00040000)`＝256KB FLASH）。
  本工程是**寄存器版**：不用 HAL / 标准库，直接读写寄存器。

> 小概念：**寄存器**就是 CPU 和外设里一个个可读写的小格子（多为 32 位）。"配置外设"＝按手册把这些格子的某几位填成想要的 0/1。

## 二、实验原理

### 2.1 单总线（1-Wire）是什么，解决什么问题

普通传感器要传数字信号，往往要用好几根线：IIC 要 2 根（SCL/SDA）、SPI 要 3~4 根（SCK/MISO/MOSI/CS）。
DS18B20 用的是 **1-Wire 单总线**：**整条总线只有一根信号线 DQ**（加上地线），主机和从机都挂在这根线上。

| 对比项 | 单总线 1-Wire | IIC | SPI |
| --- | --- | --- | --- |
| 信号线数量 | 1 根（DQ） | 2 根 | 3~4 根 |
| 谁决定"1/0" | **电平维持的时间长度** | 电平 + 时钟采样 | 时钟边沿采样 |
| 时钟线 | 没有，靠时间约定 | 有 SCL | 有 SCK |
| 典型用法 | DS18B20、DHT11、红外接收 | EEPROM、触摸屏 | FLASH、NRF24L01 |

没有时钟线，就意味着双方必须**严格约定"多少微秒算 1、多少微秒算 0"**，所以这类驱动对延时的精度极其敏感——
这正是本实验的核心：**用 SysTick 做微秒级延时，再手动翻转 GPIO 产生时序**。

总线在电气上是"**开漏输出 + 上拉电阻**"：
- 任何设备想输出 0，就使劲把线拉低（强，谁拉低谁赢）。
- 想输出 1，就**松手不驱动**（高阻），靠上拉电阻把线顶高。
- 所以代码里"输出 1"其实是"释放总线"，这也是为什么 [ds18b20.c](Drivers/BSP/DS18B20/ds18b20.c) 全程只配一种 GPIO 模式就能既发又收。

### 2.2 一次完整通信的流程（编号步骤）

单总线通信永远遵守"**复位 → ROM 命令 → 功能命令 → 数据**"这个骨架：

1. **复位**：主机把 DQ 拉低一段时间（本代码 750µs）后释放。
2. **存在脉冲**：从机（DS18B20）看到复位后，会拉低一段时间作为"我在了"的回答；主机读这根线就能判断芯片是否插好。
3. **ROM 命令**：总线上可能挂多个 1-Wire 设备，所以要先说"找谁"。本实验只有一个传感器，直接用 `0xCC`（Skip ROM，跳过寻址）。
4. **功能命令**：`0x44` = 启动温度转换（Convert T）；`0xBE` = 读暂存器（Read Scratchpad）。
5. **读数据**：DS18B20 按位往外吐数据，**低位（LSB）先出**。

代码里两次读取的完整链条（见 `ds18b20_get_temperature()`）：

```text
ds18b20_start()  : 复位 → 0xCC → 0x44(启动转换)
复位 → 0xCC → 0xBE → 读TL(低字节) → 读TH(高字节) → 换算温度
```

注意一个容易忽略的细节：`ds18b20_start()` 刚下完转换命令就立刻把结果读出来了，而 12 位分辨率的转换最多要 750ms，
所以**这次读到的其实是"上一轮转换"的结果**。程序每 100ms 读一次，数值会稳定显示，只是有一拍延迟。

### 2.3 关键时序：复位/存在脉冲、读时隙、写时隙

DS18B20 数据手册规定的时间要求，与本工程代码实际值对照（时间单位 µs）：

| 时隙 | 手册要求 | 代码实际做法 | 代码位置 |
| --- | --- | --- | --- |
| 复位脉冲 | 主机拉低 ≥480µs | 拉低 `delay_us(750)` | `ds18b20_reset()` |
| 复位后释放 | 释放后从机在 15~60µs 内开始拉低存在脉冲 | 释放后 `delay_us(15)` 再开始轮询 | `ds18b20_reset()` |
| 存在脉冲 | 从机拉低 60~240µs | 最长等 200µs 变低，再等 240µs 变高 | `ds18b20_check()` |
| 读 1 时隙 | 主机拉低 ≥1µs 后释放，**15µs 内采样**：线上为高＝1 | 拉低 2µs → 释放 12µs → 采样 → 再等 50µs | `ds18b20_read_bit()` |
| 读 0 时隙 | 同上，从机把线拉住则采样到低＝0 | 同一段代码，读到的电平不同 | `ds18b20_read_bit()` |
| 写 1 时隙 | 拉低 1~15µs 后释放，整槽 ≥60µs | 拉低 2µs → 拉高 60µs | `ds18b20_write_byte()` |
| 写 0 时隙 | 整槽拉低 ≥60µs | 拉低 60µs → 拉高 2µs | `ds18b20_write_byte()` |

**读 0 / 读 1 的本质**：主机只需要制造一个"采样窗口"。DS18B20 收到读时隙后，若这一位是 1 就不插手（线被上拉拉高），
若是 0 就强行拉住。所以**同一个 `ds18b20_read_bit()` 函数，靠采样时刻读到的电平区分 0 和 1**，无需两套时序。

**写 0 / 写 1 则相反**：由主机决定拉低多久——拉得久（≥60µs）就是写 0，拉得短（2µs 就松手）就是写 1。

### 2.4 温度寄存器、0.0625 系数与 CRC 校验

DS18B20 内部有一块 9 字节的**暂存器（Scratchpad）**，`0xBE` 命令就是把它吐出来：

| 字节 | 名称 | 内容 | 本实验是否读 |
| --- | --- | --- | --- |
| 1 | TP 数据 LSB | 温度低 8 位 | 读（`TL`） |
| 2 | TP 数据 MSB | 温度高 8 位 | 读（`TH`） |
| 3 | TH 用户字节 | 报警上限（本实验没用） | 未读 |
| 4 | TL 用户字节 | 报警下限 | 未读 |
| 5 | CONFIG | R1/R0 设置分辨率（默认 12 位） | 未读 |
| 6~8 | 计数/保留 | 用于提高分辨率 | 未读 |
| 9 | **CRC-8** | 前 8 字节的循环冗余校验值 | 未读 |

温度是**16 位带符号（补码）**数，最低 4 位是小数位：

```text
bit15..bit11 = 符号扩展位   bit10..bit4 = 温度整数部分   bit3..bit0 = 温度小数部分
```

1 个最低有效位 = 1/16 ℃ = **0.0625℃**，这就是那个系数的来历。代码为了少用浮点，把结果**放大 10 倍**返回（精度 0.1℃）：

```text
raw × 0.0625 × 10 = raw × 0.625      → 代码里就是 temp * 0.625
```

代入两个真实例子：

- 25.0625℃ → raw = 25.0625 / 0.0625 = 401 = 0x0191 → TH=0x01（≤7，正数）→ 401 × 0.625 = 250.6 → 取整 **250** → LCD 显示 `25.0`。
- −10.375℃ → raw 补码 = 0xFF5A → TH=0xFF（>7，负数）→ 按位取反得 0x00A5 = 165 → (165+1) × 0.625 = 103.75 → 取整 103 → 加负号 **-103** → LCD 显示 `-10.3`。

> 为什么负数要"取反 +1"？补码规则就是如此。代码注释解释得很清楚：先在取反后不 +1，
> 到换算那一步再 `(temp + 1) * 0.625`，是为了避免低位 +1 产生进位时代码变啰嗦。

**关于 CRC 校验**：正规做法是把 9 个字节全读回来，用多项式 x⁵+x⁴+x²+1（DS18B20 用的 CRC-8）算一遍前 8 字节，
和第 9 字节比对，不一致就丢弃本次数据。**本实验代码只读了 TL、TH 两个字节，没有做 CRC 校验**，
所以强干扰下可能显示一个"看起来合理但其实错"的温度（详见第八章与第九章延伸练习）。

### 2.5 微秒级延时是怎么做到的（单总命的命根子）

单总线要求 1~2µs 的精度，`for` 空循环数指令那种延时在不同优化等级下会飘，本工程改用 **SysTick 计数 + "时钟摘取法"**
（[delay.c](Drivers/SYSTEM/delay/delay.c)）：

1. `delay_init(72)`：`SysTick->CTRL |= (1 << 2)` 选**内部时钟 HCLK = 72MHz**；`SysTick->LOAD = 0X0FFFFFFF`（24 位最大值）；
   `g_fac_us = sysclk` ＝ 72，即 **1µs 对应 72 个计数**。
2. `delay_us(nus)`：`ticks = nus * 72`；然后反复读 `SysTick->VAL`（递减计数器），把每次"减掉了多少"累加进 `tcnt`，
   `tcnt >= ticks` 就退出。跨过一次重载时按 `reload - tnow + told` 补偿。

这样得到的延时是**真的按硬件时钟数出来的**，不受编译优化、代码条数影响；
`delay_ms(nms)` 内部也就是 `delay_us(nms * 1000)`。DS18B20 的 750µs / 15µs / 2µs / 12µs / 60µs 全靠它撑着。

### 2.6 寄存器版怎么配这根 DQ 线

| 要做的事 | 寄存器 | 本实验填的值及含义 |
| --- | --- | --- |
| 开 GPIOA 时钟 | `RCC->APB2ENR` | bit2（`|= 1 << 2`）＝IOPA，不开时钟写 GPIO 无效 |
| 配 PA1 为 10MHz 开漏输出 | `GPIOA->CRL` | 引脚 1 占 bit[7:4]，填 `0x5`＝CNF=01(开漏输出)+MODE=01(10MHz) |
| 拉低/释放 DQ | `GPIOA->BSRR` | 置 1 高 16 位写 0（BSRR bit17＝复位），高 16 位写 1（BSRR bit1＝置位） |
| 读 DQ 电平 | `GPIOA->IDR` | 读 bit1，开漏输出释放后照样能读外部电平 |

`CRL`/`CRH` 是 F103 的特色：每个引脚占 4 位，PA0~PA7 在 `CRL`、PA8~PA15 在 `CRH`。
本工程把这些封装成了 `sys_gpio_set()`（[sys.c](Drivers/SYSTEM/sys/sys.c)），传入的参数会被翻译成 CNF/MODE 四位值。

**外接模块怎么插**：官方 `readme.txt` 要求自备 DS18B20 一个，插在开发板 **U6 位置**（按丝印插，**平面朝内、靠左插上去**）。
插反/插歪通常表现为一直提示 `DS18B20 Error`。

**引脚冲突提醒**：代码里 DS18B20 和实验24 的 DHT11 **都定义在 PA1**，实验25 的 NRF24L01 IRQ 也在 PA1。
所以同一块板上，这几个模块不能同时插、同时测，否则信号线并在一起互相干扰。

**时钟树对本实验意味着什么**：`sys_stm32_clock_init(9)` 把 8MHz 外部晶振经 PLL 9 倍频到 72MHz，
得到 `HCLK = PCLK2 = 72MHz`、`PCLK1 = 36MHz`。这条链上 PA1 属于 APB2 外设（GPIO 时钟由 APB2ENR 开），
而 `delay_init(72)` 里的 72 就是"每微秒 72 个计数"的来源——**主频设错，单总线时序全乱**。

## 五、核心代码解析

### 5.1 初始化：`ds18b20_init()`

```c
uint8_t ds18b20_init(void)
{
    DS18B20_DQ_GPIO_CLK_ENABLE();   /* 开启DQ引脚时钟 */

    /* DS18B20_DQ引脚模式设置,开漏输出,上拉, 这样就不用再设置IO方向了, 开漏输出的时候(=1), 也可以读取外部信号的高低电平 */
    sys_gpio_set(DS18B20_DQ_GPIO_PORT, DS18B20_DQ_GPIO_PIN,
                 SYS_GPIO_MODE_OUT, SYS_GPIO_OTYPE_OD, SYS_GPIO_SPEED_MID, SYS_GPIO_PUPD_PU);

    ds18b20_reset();
    return ds18b20_check();
}
```

逐段看：

1. `DS18B20_DQ_GPIO_CLK_ENABLE()` 展开是 `RCC->APB2ENR |= 1 << 2`，即打开 GPIOA 时钟（bit2 = IOPA）。
2. GPIO 参数：模式 `SYS_GPIO_MODE_OUT`(1)、输出类型 `SYS_GPIO_OTYPE_OD`(1＝开漏)、速度 `SYS_GPIO_SPEED_MID`(1＝10MHz)。
   在 `sys_gpio_set()` 里被翻译成 4 位配置 `0x5`：MODE=01（输出 10MHz）、CNF=01（开漏输出），写到 `GPIOA->CRL` 的 bit[7:4]。
3. **一个坑**：第 6 个参数 `SYS_GPIO_PUPD_PU` 在输出模式下其实**不起作用**——`sys_gpio_set()` 只在输入模式分支里操作上下拉，
   函数注释也写了"在输出模式下, pupd 参数无效!!（开漏输出无法使用内部上拉电阻!!）"。
   线被释放后的默认高电平靠**板上的外部上拉电阻**，不是内部上拉。
4. 全程不再切换输入/输出方向：开漏 + `IDR` 读取，让同一根线既能"拉"又能"看"，这是单总线驱动最常见的写法。
5. 返回值就是 `ds18b20_check()`：0 表示有存在脉冲（正常），1 表示没检测到。

### 5.2 复位与存在脉冲：`ds18b20_reset()` / `ds18b20_check()`

```c
static void ds18b20_reset(void)
{
    DS18B20_DQ_OUT(0);  /* 拉低DQ,复位 */
    delay_us(750);      /* 拉低750us */
    DS18B20_DQ_OUT(1);  /* DQ=1, 释放复位 */
    delay_us(15);       /* 延迟15US */
}
```

```c
while (DS18B20_DQ_IN && retry < 200)        /* 等待DQ变低, 等待200us */
{
    retry++;
    delay_us(1);
}
if (retry >= 200) { rval = 1; }
else
{
    retry = 0;
    while (!DS18B20_DQ_IN && retry < 240)   /* 等待DQ变高, 等待240us */
    { retry++; delay_us(1); }
    if (retry >= 240) rval = 1;
}
```

- `DS18B20_DQ_OUT(0)` → `sys_gpio_pin_set(GPIOA, SYS_GPIO_PIN1, 0)` → `GPIOA->BSRR |= pin << 16`，把 PA1 拉低。
- `DS18B20_DQ_OUT(1)` → `GPIOA->BSRR |= pin`，开漏模式下等于"松手"，线被上拉拉高。
- `DS18B20_DQ_IN` → 读 `GPIOA->IDR` 的 bit1。
- `check` 用两个"最多等多少微秒"的循环代替硬延时：**先等它变低（存在脉冲来了），再等它变高（脉冲结束）**，
  任何一步超时（200µs / 240µs）就判定异常返回 1。这种写法比死等更抗干扰，也是"芯片在不在"的判据。

### 5.3 读位与写字节：时间就是数据

```c
static uint8_t ds18b20_read_bit(void)
{
    uint8_t data = 0;
    DS18B20_DQ_OUT(0);
    delay_us(2);
    DS18B20_DQ_OUT(1);
    delay_us(12);
    if (DS18B20_DQ_IN) { data = 1; }
    delay_us(50);
    return data;
}
```

拉低 2µs 发起时隙 → 释放 → 12µs 后采样（合计 14µs，仍在手册要求的 15µs 窗口内）→ 再补 50µs 让时隙满 60µs。

```c
for (j = 1; j <= 8; j++)
{
    if (data & 0x01)
    {
        DS18B20_DQ_OUT(0);  /*  Write 1 */
        delay_us(2);
        DS18B20_DQ_OUT(1);
        delay_us(60);
    }
    else
    {
        DS18B20_DQ_OUT(0);  /*  Write 0 */
        delay_us(60);
        DS18B20_DQ_OUT(1);
        delay_us(2);
    }
    data >>= 1;             /* 右移,获取高一位数据 */
}
```

- 写：**低位先发**，所以每轮取 `data & 0x01` 再右移。
- 读字节同理，`data |= b << i`（i 从 0 到 7），把先读到的低位放在低位。
- DS18B20 的"读"其实是主机每发一个时隙、从机就在里面回一位，所以 `read_byte()` 必须是 8 个独立时隙。

### 5.4 温度换算：`ds18b20_get_temperature()`

```c
ds18b20_start();            /*  ds1820 start convert */
ds18b20_reset();
ds18b20_check();
ds18b20_write_byte(0xcc);   /*  skip rom */
ds18b20_write_byte(0xbe);   /*  convert */
TL = ds18b20_read_byte();   /*  LSB */
TH = ds18b20_read_byte();   /*  MSB */

if (TH > 7)
{
    TH = ~TH;
    TL = ~TL;
    flag = 0;   /* 温度为负 */
}
temp = TH;      /* 获得高八位 */
temp <<= 8;
temp += TL;     /* 获得底八位 */
if (flag == 0)
{   /* 将温度转换成负温度，这里的+1参考前面的说明 */
    temp = (double)(temp + 1) * 0.625;
    temp = -temp;
}
else
{
    temp = (double)temp * 0.625;
}
```

- `TH > 7` 是**符号判断**：TH 的低 4 位是整数高位，bit7（值为 0x80）才是符号扩展位。只要 TH > 7，说明 bit7 是 1，温度为负。
- 负数按补码"取反 +1"还原成绝对值，再乘 0.625（= 0.0625℃ × 10）。
- 函数返回的是**放大 10 倍**的整数：`-550 ~ 1250`，对应 −55.0℃ ~ 125.0℃（DS18B20 的量程）。

### 5.5 主循环与显示

```c
temperature = ds18b20_get_temperature();
if (temperature < 0)
{
    lcd_show_char(30 + 40, 130, '-', 16, 0, BLUE);  /* 显示负号 */
    temperature = -temperature;                     /* 转为正数 */
}
else
{
    lcd_show_char(30 + 40, 130, ' ', 16, 0, BLUE);  /* 去掉负号 */
}
lcd_show_num(30 + 40 + 8, 130, temperature / 10, 2, 16, BLUE);  /* 显示正数部分 */
lcd_show_num(30 + 40 + 32, 130, temperature % 10, 1, 16, BLUE); /* 显示小数部分 */
```

模板串 `"Temp:   . C"` 用空格占好位，之后每次只覆盖那三个数字：
负号/空格在 x=70，整数两位在 x=78、86，小数一位在 x=102（小数点由模板里的 `.` 提供）。
`/10` 取整数部分、`%10` 取一位小数，正好还原"放大 10 倍"的约定。

## 七、实验现象

1. 上电后 LCD 依次显示 `STM32` / `DS18B20 TEST` / `ATOM@ALIENTEK`。
2. **没插/插反 DS18B20**：LCD 第 4 行反复出现又消失 `DS18B20 Error`（200ms 显示 + 200ms 擦除），程序卡在 `while (ds18b20_init())` 里。
3. **插好 DS18B20**：显示 `DS18B20 OK`，下面出现 `Temp:   . C`，随后温度数字每 100ms 刷新一次。
4. 用手指捏住传感器探头，温度缓慢上升；用棉签蘸酒精擦拭或对着它吹气，温度下降；
   温度低于 0℃ 时最左边出现 `-` 号（一般家用场景见不到，可用冰盐水管出来）。
5. LED0（PA8 红灯）每 200ms 左右翻转一次，表示程序在主循环里跑。

## 八、注意事项

- **时序就是命**：`delay_us()` 依赖 SysTick 按 72MHz 计数。若你把 `sys_stm32_clock_init(9)` 改成别的倍频、
  或忘了 `delay_init(72)`，750µs/15µs 就不准了，现象通常是"有时能检测到、有时 Error"或温度乱跳。
- **不要在关中断/长中断里调单总线读写**：中断插进来会把时隙拉长，DS18B20 直接读错。本实验没开什么中断，串口中断
  偶尔打进来一般还能容错（时隙余量较大），但移植到带 RTOS/多中断的项目时要小心。
- **开漏 + 外部上拉**：代码传入的 `SYS_GPIO_PUPD_PU` 在输出模式下不生效（`sys_gpio_set()` 的实现只在输入模式操作上下拉），
  线上高电平来自板载上拉。若你自己把 DS18B20 接到杜邦线拉得很长的实验板上，建议补一个 4.7kΩ 上拉电阻。
- **一次转换要花时间**：12 位分辨率下转换最长 750ms，本例每 100ms 读一次且"读完上一轮的结果再启动下一轮"，
  所以刚上电第一帧数值可能不准，等几拍再看。
- **没做 CRC 校验**：驱动只读暂存器前 2 字节，第 9 字节的 CRC-8 没用。要求可靠时应把 9 字节读全并校验（见延伸练习 2）。
- **大于等于 100℃ 显示会截断**：`lcd_show_num(..., temperature / 10, 2, ...)` 只给 2 位，125.0℃ 会显示成 `25.0`。
  DS18B20 量程上限就是 125℃，做加热实验时留意别误判。
- **官方 `readme.txt` 与代码的差异**：readme 的"硬件资源"里列了独立按键 KEY0(PC5)/KEY1(PA15)/KEY_UP(PA0)，
  但本实验代码里**没有 KEY 驱动、也没用到按键**（`readme.txt` 是模板通用段落）。其余引脚描述（LED0 PA8、LED1 PD2、
  串口1 PA9/PA10、DS18B20 插 U6）与代码一致。
- **模块别插反**：U6 座子要"平面朝内、靠左"插；插反一般只是检测不到，但请**先断电再调整**，别带电硬掰。
- **源码是 GBK 编码**：用编辑器打开中文注释前确认编码为 GBK/GB2312，否则注释乱码（本 README 是 UTF-8）。

## 九、总结与延伸

**本实验要点：**

1. 单总线只靠一根 DQ 传数据，**用"电平维持多久"表示 0/1**，所以复位/存在脉冲、读时隙、写时隙的时间必须精确。
2. 寄存器版做法：`RCC->APB2ENR` 开 GPIOA 时钟 → `GPIOA->CRL` 把 PA1 配成 `0x5`（10MHz 开漏输出）→
   `BSRR` 拉低/释放、`IDR` 读电平，一套配置搞定收发。
3. 通信骨架：复位 → `0xCC`(Skip ROM) → `0x44`(启动转换) / `0xBE`(读暂存器) → 低位先行的字节流。
4. 温度是 16 位补码、LSB=0.0625℃；代码乘 `0.625` 得到放大 10 倍的 0.1℃ 值，`/10` 与 `%10` 分别显示整数和小数。
5. µs 延时由 SysTick 72MHz"时钟摘取法"提供，这是所有单总线驱动的公共依赖。

**延伸小练习：**

1. 把读取周期从 100ms 改成 1s：把 `if (t % 10 == 0)` 改成 `if (t % 100 == 0)`（`t` 每圈 +1、每圈 `delay_ms(10)`），
   观察温度刷新变慢，顺便体会"转换时间 750ms"的意义。
2. 给驱动加 CRC-8 校验：在 `ds18b20_get_temperature()` 里把 9 个字节全读进数组，按多项式 x⁵+x⁴+x²+1
   逐位移位异或算 CRC，和 `buf[8]` 比对，不一致就返回上一次的有效值并通过串口打印一次错误计数。
3. 用串口输出温度：在 `if (t % 10 == 0)` 分支里加 `printf("T = %d.%d C\r\n", temperature / 10, temperature % 10);`
   （`usart.c` 已重定向 `fputc`），接 115200 串口助手就能把数据存到电脑上画曲线。

**衔接**：实验24 DHT11 用的是同一根 PA1、同一套"复位—存在脉冲—按位读写"的思路，但 DHT11 是**从机自己决定 0/1 的高电平宽度**，
主机在固定时刻采样；把两个实验的时序表放在一起对比，单总线的味道就完全懂了。
