# 实验5 独立看门狗实验

> 一句话概括：让程序必须"按时喂狗"，一旦卡死超过 1 秒没喂，芯片自动复位重启——这就是独立看门狗（IWDG）防跑飞的原理。

## 一、实验简介

- **实验目的**（官方 `readme.txt`）：学习独立看门狗（IWDG）的使用。
  通俗讲：单片机的程序有时会因为干扰、死循环、跑飞而"卡住不动"。看门狗就是一个独立的倒计时器，
  你必须在规定时间内不断"喂狗"（把倒计时重新装满）；如果程序卡住忘了喂，倒计时到 0 就直接把芯片复位，
  让它从头再跑，从而把系统救回来。
- **在学习路线中的位置**：前置实验是「实验1 跑马灯 / LED」「按键输入实验」（本实验要用按键喂狗、用 LED 观察现象）；
  后续可衔接「实验6 窗口看门狗」（进阶版，多了"窗口"限制和提前唤醒中断）。
- **开发板与芯片**：正点原子 MiniSTM32 V4 开发板，主芯片 STM32F103RC（Keil 工程里的器件即 `STM32F103RC`）。
  本工程是**寄存器版**——不用 HAL/标准库函数，直接往寄存器里按位填数。

> 小概念：**寄存器**就是 CPU 内部和外设里一个个可以读写的"控制格子"。配置外设 = 按手册把对应的格子填上正确的 0/1。

## 二、实验原理

### 2.1 什么是"独立"看门狗

STM32 有两种看门狗，本实验用的是 **IWDG（Independent Watchdog，独立看门狗）**。"独立"指的是：

- 它用的是芯片内部**独立的低速时钟 LSI**（Internal Low Speed oscillator，典型约 40kHz），
  而**不是**主时钟 72MHz。
- 因为时钟独立、且逻辑很简单，**即使主时钟晶振停振、PLL 出错，看门狗照样在倒数**，可靠性高。
- **一旦启动，除复位外无法关闭**——这是它和"窗口看门狗"最大的操作差异，务必记住。

### 2.2 它怎么倒计时（递减计数器 +  reload）

IWDG 内部就是一个"往下减的计数器"：装载一个初值后，每个 LSI 时钟周期减 1，减到 0 就触发复位。
"喂狗"就是把自动重装载寄存器 `IWDG->RLR` 里的值重新灌回计数器，让它再从大往小减。

### 2.3 关键寄存器（本实验只用到 4 个）

IWDG 结构体（见 [stm32f103xe.h](Drivers/CMSIS/Device/ST/STM32F1xx/Include/stm32f103xe.h)）：

| 寄存器 | 偏移 | 作用 | 本实验怎么写 |
| --- | --- | --- | --- |
| `IWDG->KR`  | 0x00 | 钥匙寄存器（Key），写特定"密码"才生效 | `0x5555` 解锁、`0xAAAA` 喂狗/reload、`0xCCCC` 启动 |
| `IWDG->PR`  | 0x04 | 预分频（Prescaler），决定减 1 有多快 | 写入 `prer`（本工程 = 4） |
| `IWDG->RLR` | 0x08 | 自动重装载值（Reload），倒计时初值 | 写入 `rlr`（本工程 = 625） |
| `IWDG->SR`  | 0x0C | 状态位 `PVU`(bit0)/`RVU`(bit1)，表示 PR/RLR 正在被更新 | 本例未查询（可查询以等待写生效） |

- `KR` 写 `0x5555`：**解锁**，允许接下来改写 `PR` 和 `RLR`（否则这俩寄存器是只读的，防误操作）。
- `KR` 写 `0xAAAA`：**reload**，把 `RLR` 重新装进计数器——这就是"喂狗"。
- `KR` 写 `0xCCCC`：**启动**看门狗，从此开始倒数（启动后不能停）。

### 2.4 超时时间怎么算（代入本工程数值）

`PR` 决定的分频系数为 `分频因子 = 4 * 2^prer`（最大 256）。溢出时间（LSI 约 40kHz）：

```text
Tout = (分频因子 * RLR) / 40   单位: ms
     = ((4 * 2^prer) * rlr) / 40
```

本实验 `iwdg_init(4, 625)`，代入：

- prer = 4 → 分频因子 = 4 * 2^4 = 4 * 16 = **64**
- rlr = 625
- Tout = (64 * 625) / 40 = 40000 / 40 = **1000 ms = 1 秒**

也就是代码注释里写的"预分频数为 64，重载值为 625，溢出时间为 1s"。超过 1 秒没喂 → 复位。

### 2.5 复位标志 RCC->CSR 的读取（拓展概念）

看门狗把芯片复位后，程序从 `main()` 重新起跑。那怎么知道"这次重启是被看门狗复位的，还是正常上电/按复位键"？
答案在 **`RCC->CSR`（控制/状态寄存器）** 的高位里，有一组"复位标志"，一旦发生过对应复位就会被硬件置 1（需软件清除）：

| 位 | 宏名（CMSIS 中真实存在） | 含义 |
| --- | --- | --- |
| bit26 | `RCC_CSR_PINRSTF` | 复位引脚（NRST 键）复位 |
| bit27 | `RCC_CSR_PORRSTF` | 上电/掉电复位 |
| bit28 | `RCC_CSR_SFTRSTF` | 软件复位 |
| bit29 | `RCC_CSR_IWDGRSTF` | **独立看门狗复位**（本实验关心的） |
| bit30 | `RCC_CSR_WWDGRSTF` | 窗口看门狗复位 |
| bit24 | `RCC_CSR_RMVF` | 写 1 清除以上所有复位标志 |

读取思路：程序一进入就 `if (RCC->CSR & (1<<29)) { /* 上次是 IWDG 复位 */ }`，读完后可 `RCC->CSR |= (1<<24)` 清除标志。
**说明**：本实验的官方 `main.c` 只用 LED 现象体现复位，并没有实际去读 `RCC->CSR`；上面这些位名都取自工程内的 CMSIS 头文件，
可作为延伸练习自行加上（见"九、总结与延伸"）。

## 四、代码结构与调用流程

```text
实验5 独立看门狗实验/
├── User/main.c                 主程序：初始化 + 主循环里判断按键喂狗
├── Drivers/BSP/WDG/wdg.c/.h    独立看门狗驱动：iwdg_init / iwdg_feed
├── Drivers/BSP/KEY/key.c/.h    按键驱动：key_init / key_scan（读 WK_UP）
├── Drivers/BSP/LED/led.c/.h    LED 驱动：led_init、LED0/LED1 宏
└── Drivers/SYSTEM/{sys,delay,usart}  时钟/延时/串口底层公共代码
```

各文件职责：`wdg.c` 只负责配置 IWDG 与喂狗；`key.c` 负责扫描按键；`led.c` 负责点亮观察用 LED；`SYSTEM` 目录提供时钟、SysTick 延时、串口打印。

**`main()` 流程**（见 [User/main.c](User/main.c)）：

1. `sys_stm32_clock_init(9)`：系统时钟 72MHz。
2. `delay_init(72)`：初始化延时。
3. `usart_init(72, 115200)`：初始化串口 1（本工程现象靠 LED，串口备用）。
4. `led_init()`、`key_init()`：初始化 LED 与按键。
5. `delay_ms(100)`：**先延时 100ms 再开看门狗**，让 `LED0` 的初始变化肉眼可见。
6. `iwdg_init(4, 625)`：启动 IWDG，溢出时间 1s（启动后不可关闭）。
7. `LED0(0)`：点亮红灯。
8. 进入 `while(1)`：`if (key_scan(0)==WKUP_PRES) iwdg_feed();`，再 `delay_ms(10)`。

主循环文字流程：`扫描按键 → 是 WK_UP 按下? → 是: 喂狗(reload) → 否: 不喂 → 延时 10ms → 回到开头`。
只要你不按，1 秒后看门狗溢出 → 芯片复位 → `main()` 又从头跑一遍。

## 五、核心代码解析

### 5.1 初始化并启动 IWDG —— `iwdg_init`

摘自 [Drivers/BSP/WDG/wdg.c](Drivers/BSP/WDG/wdg.c)：

```c
void iwdg_init(uint8_t prer, uint16_t rlr)
{
    IWDG->KR = 0X5555;  /* 使能对IWDG->PR和IWDG->RLR的写 */
    IWDG->PR = prer;    /* 设置分频系数 */
    IWDG->RLR = rlr;    /* 从加载寄存器 IWDG->RLR */
    IWDG->KR = 0XAAAA;  /* reload */
    IWDG->KR = 0XCCCC;  /* 使能看门狗 */
}
```

逐句解释：

1. `KR=0x5555`：解锁。因为 `PR`/`RLR` 默认是只读的，必须先写这个密码才能改。
2. `PR=prer`（=4）：设分频因子 = 4×2^4 = 64，控制计数器减 1 的速度。
3. `RLR=rlr`（=625）：装倒计时初值。
4. `KR=0xAAAA`：先把新值 reload 进计数器，保证启动瞬间计数值有效。
5. `KR=0xCCCC`：正式启动。**执行到这一行，看门狗就再也关不掉了**，只能靠复位停止。

> 为什么顺序必须是"解锁→改 PR/RLR→reload→启动"？没写 `0x5555` 时改 `PR/RLR` 会被硬件忽略；
> 没写 `0xCCCC` 则根本不倒数。

### 5.2 喂狗 —— `iwdg_feed`

```c
void iwdg_feed(void)
{
    IWDG->KR = 0XAAAA;  /* reload */
}
```

喂狗本质就是再写一次 `0xAAAA`，把 `RLR` 重新装进计数器，让倒数归零重开。

### 5.3 主循环与按键判断

[User/main.c](User/main.c) 主循环：

```c
    while (1)
    {
        if (key_scan(0) == WKUP_PRES) /* 如果WK_UP按下,则喂狗 */
        {
            iwdg_feed();        /* 喂狗 */
        }

        delay_ms(10);
    }
```

- `key_scan(0)` 参数 0 表示"不支持连按"，即按住不放只认第一次，必须松开再按才重新返回键值——
  这正好符合"按一下喂一次狗"的用法。
- `WKUP_PRES` 值是宏定义的 3（[key.h](Drivers/BSP/KEY/key.h)），代表 WK_UP（PA0）被按下。
- `delay_ms(10)` 是扫描节拍兼去抖，约每 10ms 判断一次按键。

3. 编译产物（`.axf`/`.hex`）在 `Projects/MDK-ARM/` 下的输出目录。

## 七、实验现象

对照官方"实验现象"，可核对如下：

1. 上电/下载后，程序初始化完成即点亮 LED0（红灯），进入主循环。
2. **持续按住/反复按 WK_UP 按键**：每按一次喂一次狗，看门狗永远到不了 0，LED0 **常亮不熄**。
3. **停止喂狗**：从最后一次喂狗起算，1 秒（Tout）内没再按，IWDG 计数器减到 0 → **芯片复位**。
   复位后 `led_init()` 先把 LED0 熄灭（`LED0(1)`），随后程序重新点亮，因此你会看到 **LED0 灭一下再亮**，
   看起来就是 LED0 在"一闪一闪"——这一闪就是一次看门狗复位。

## 八、注意事项

- **看门狗一旦 `0xCCCC` 启动就不能关**：想在调试里停下来，要么别启狗，要么在复位后重新配置。
- **喂狗要真的"有间隔地喂"**：本例靠人按 WK_UP。真实项目里应在主循环/任务里定期喂，绝不能喂得太勤
  （比如每 1ms 喂一次）——那样看门狗形同虚设，程序卡死前如果刚好喂过就救不回来。
- **KEY1 在 PA15**：PA15 复位后默认是 JTAG 的 JTDI 功能，本工程只用它做输入、不常用，一般不影响；
  若你换成 SWD 调试（只用 SWDIO/SWCLK）则 PA15 可放心当普通 GPIO。
- **`delay_ms(100)` 不能省**：它让 LED0 的开灯动作在开狗前"看得见"，否则启动太快不易观察初始状态。
- **代码与官方说明一致性**：官方 `readme.txt` 说"溢出时间 Tout=1s"，与代码 `iwdg_init(4,625)` 算得的 1000ms **一致**，无差异。
- **源码编码为 GBK**：用支持的编辑器打开，中文注释才不乱码；本 README 为 UTF-8。

## 九、总结与延伸

**本实验要点：**

1. IWDG 用独立 LSI（约 40kHz），与主时钟无关，掉主时钟也能复位救场。
2. 靠 `KR` 的三个"密码"（0x5555 解锁 / 0xAAAA 喂狗 / 0xCCCC 启动）操作，PR/RLR 决定超时。
3. 超时公式 `Tout = ((4*2^prer)*rlr)/40 ms`，本工程代入得 1s。
4. 喂狗 = reload 计数器；忘喂 → 复位，用 LED 能观察到。

**延伸小练习：**

1. 把 `iwdg_init(4, 625)` 改成 `iwdg_init(4, 312)`，算一下溢出时间应约 0.5s，观察 LED 闪烁是否变快。
2. 在 `main()` 开头加一段读 `RCC->CSR` 的代码：若 `RCC->CSR & RCC_CSR_IWDGRSTF` 非 0 就经串口打印"看门狗复位!"，
   读完用 `RCC->CSR |= RCC_CSR_RMVF;` 清标志——把本实验"看现象"升级成"看复位原因"。
3. 去掉主循环里的 `iwdg_feed()`，让程序必定 1s 复位一次，用万用表/逻辑分析仪或计数验证复位周期。

**衔接**：理解了"到点就复位"后，下一个「实验6 窗口看门狗」会引入"提前唤醒中断"，
让你在真正复位前先有一次"抢救/保存现场"的机会，喂狗时机也从"越快越好"变成"落在窗口内才行"。
