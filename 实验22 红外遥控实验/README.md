# 实验22 红外遥控实验

> 一句话概括：用 STM32 的"外部中断/定时器输入捕获 + 计数器"去解读一个红外遥控器发出的 NEC 编码，把按下的按键值和含义显示在 LCD 上，学会"用时间宽度来读一串 0 和 1"的解码思路。

## 一、实验简介

- **实验目的**（官方 `readme.txt`）：学习红外遥控器的使用。
  通俗展开：遥控器里有一颗红外 LED，按下按键时它以 38kHz 载波"一闪一闪"地发 coded 光；开发板上的红外接收头把光转成电平信号。我们要做的，就是**精确量出每一段电平持续了微秒级的多长时间**，据此还原出发的是哪一串 0/1，最终查表得到"按的是哪个键"。
- **在学习路线中的位置**：
  - 前置：GPIO 输入实验、定时器实验（尤其是**输入捕获**）、LCD 显示实验。
  - 后续：本实验把"定时器捕获 + 中断服务"组合成一个完整协议解码器，为后面学习单总线（DS18B20）、其它时序协议打下"靠时间读数"的思维基础。
- **开发板与芯片**：正点原子 MiniSTM32 V4，主芯片 STM32F103RC，主频 72MHz；配件为 ALIENTEK 红外遥控器。

## 二、实验原理

### 2.1 红外遥控的载体：38kHz 红外光

红外遥控器发的不是普通可见光，而是波长约 940nm 的红外光，并用 **38kHz 的载波**去"开关"这颗 LED（这叫 PWM 调制）。开发板上的**一体式红外接收头**（如 VS1838B 一类，内含接收管+放大+带通滤波+解调）只认 38kHz 载波，能自动滤掉日光、灯光等干扰。它的特点是"**低电平有效**"：

- 没收到信号（空闲）→ 输出高电平（1）；
- 收到 38kHz 载波（发码）→ 输出低电平（0）。

所以 STM32 收到的电平正好是"反过来的"：发码时线是低、停发时线是高。我们测量的就是这些高低电平各自持续多少微秒。

### 2.2 NEC 协议：用时间宽度区分 0 和 1

正点原子遥控器采用最常见的 **NEC 协议**。一帧数据由"引导码 + 32 位数据 + （连发时的重复码）"组成，关键是用**脉冲的时长**编码信息（单位 µs，标准值）：

| 名称 | 组成 | 时长 | 代码判定区间(dval，µs) |
| --- | --- | --- | --- |
| 引导码 | 4.5ms 载波 + 4.5ms 空闲 | 共 9ms | 高电平段 4200~4700（≈4.5ms） |
| 逻辑 "0" | 0.5625ms 载波 + 0.5625ms 空闲 | 共 1.125ms | 高电平段 300~800（≈0.56ms） |
| 逻辑 "1" | 0.5625ms 载波 + 1.6875ms 空闲 | 共 2.25ms | 高电平段 1400~1800（≈1.68ms） |
| 重复码 | 4.5ms 载波 + 2.25ms 空闲 | 共 6.75ms | 高电平段 2000~3000（≈2.5ms） |

> 直观记法：引导码看"长不高"——9ms；bit0 短、bit1 长（都从 0.5625ms 的载波起头，区别在后面空闲是 0.5625 还是 1.6875ms）。代码里量的正是这段**高电平（空闲）时间**。

32 位数据的排布（每字节都带一个反码做校验，先传低位 LSB）：

```
[ 8位地址码 ][ 8位地址反码 ][ 8位命令码 ][ 8位命令反码 ]
```

地址码用来区分是哪一款遥控器（本工程 `REMOTE_ID = 0`），命令码就是真正的"键值"。

### 2.3 怎么"量时间"：输入捕获 + 定时器

STM32 定时器的**输入捕获**功能：当指定引脚上出现一个边沿（上升沿/下降沿）时，硬件自动把当前计数值 `CNT` 锁存到 `CCR` 寄存器，并可触发中断。本实验用它来量脉宽，思路如下：

1. 让 PA1 接到 TIM5 通道 2 的捕获输入。
2. **先捕获上升沿**：当信号从 0→1 跳变时，把计数器 `CNT` 清零开始计时，并记下"上升沿已捕获"。
3. **再捕获下降沿**：当信号从 1→0 跳变时，读取 `CCR`——这就是刚刚那段**高电平持续了多少 µs**（因为计数器以 1µs/次在加）。读完后把捕获切回上升沿，重复。

这样每一个高低电平的宽度都被精确量出来，再对照 2.2 的表就能判定引导码、0、1、重复码。

### 2.4 参数计算（定时器时基）

TIM5 挂在 APB1，APB1 预分频为 2（PCLK1=36MHz），定时器时钟自动 ×2 = **72MHz**。见 [remote.c](Drivers/BSP/REMOTE/remote.c) 的 `remote_init()`：

```
计数频率 = TIM5_CLK / (PSC+1) = 72MHz / (71+1) = 1MHz   → 每计 1 个数 = 1µs
溢出时间 = (ARR+1) / 计数频率 = 10000 / 1MHz = 10000µs = 10ms
```

- `PSC = 72 - 1 = 71`：把 72MHz 降到 1MHz，实现 1µs 分辨率，正好够量 µs 级脉宽。
- `ARR = 10000`：最大计到 10ms 就溢出，用来做"一帧结束/连发"的超时计时。

### 2.5 状态机：接收状态字节 `g_remote_sta`

由于解码要跨中断拼出 32 位，程序用一个字节记录状态（见 remote.c 注释）：

| 位 | 含义 |
| --- | --- |
| bit7 | 是否收到了引导码 |
| bit6 | 是否已完整采集到一次按键的 32 位 |
| bit4 | 上升沿是否已被捕获（防止重复处理） |
| bit3:0 | 10ms 溢出计时器 |

每收到一个逻辑位，就往 `g_remote_data` 里移位拼装（先到的位放低位）。10ms 溢出中断用来判断"这一帧传完了"（置 bit6）以及遥控器是否还在长按（连发计数）。

## 三、硬件资源与接线

| 资源 | 引脚 | 代码中的宏/位置 | 说明 |
| --- | --- | --- | --- |
| 红外数据输入 RDATA | PA1 | `REMOTE_IN_GPIO_PIN`，[remote.h](Drivers/BSP/REMOTE/remote.h) | 上拉输入，接接收头 OUT 脚 |
| 捕获定时器 | TIM5 通道2 | `REMOTE_IN_TIMX=TIM5`，`REMOTE_IN_TIMX_CHY=2` | 输入捕获量脉宽 |
| TIM5 时钟使能 | RCC->APB1ENR bit3 | `REMOTE_IN_TIMX_CHY_CLK_ENABLE()` | TIM5 在 APB1 |
| LED0（红灯） | PA8 | `LED0`，[led.h](Drivers/BSP/LED/led.h) | 低电平点亮，运行指示 |
| 串口1 | PA9/PA10 | [usart.h](Drivers/SYSTEM/usart/usart.h) | 波特率 115200 |
| TFTLCD 模块 | 8080 并口 | [lcd.h](Drivers/BSP/LCD/lcd.h) | 仅支持 MCU 屏，不支持 RGB 屏 |

- **一体式红外接收头**：一般通过排针/转接座接开发板，其 OUT 接 **PA1**，VCC 接 3.3V，GND 接 GND。接收头是"低有效"，所以代码把 PA1 设为**上拉输入**（空闲时被上拉保持高电平）。
- 串口调试需 USART1 排针上 PA9→TXD、PA10→RXD 跳线帽连好（板载 CH340）。
- **时钟**：`sys_stm32_clock_init(9)` = 8MHz 晶振 × PLL9 = 72MHz，是 2.4 节 TIM5 计时的基础。

## 五、核心代码解析

### 5.1 初始化（PA1 + TIM5 捕获）

```c
sys_gpio_set(REMOTE_IN_GPIO_PORT, REMOTE_IN_GPIO_PIN,
             SYS_GPIO_MODE_IN, ..., SYS_GPIO_PUPD_PU);   /* PA1 上拉输入 */

REMOTE_IN_TIMX->ARR = 10000;    /* 10ms 溢出 */
REMOTE_IN_TIMX->PSC = 72 - 1;   /* 1MHz，1µs 计数一次 */

REMOTE_IN_TIMX->CCMR1 |= 1 << 8 * (chy - 1);   /* CC2S=01：IC2 映射到 TI2 */
REMOTE_IN_TIMX->CCMR1 |= 0 << (2 + 8*(chy-1)); /* 不分频，全捕获 */
REMOTE_IN_TIMX->CCMR1 |= 0 << (4 + 8*(chy-1)); /* 不滤波 */

REMOTE_IN_TIMX->CCER  |= 1 << (4 * (chy - 1)); /* CC2E=1 使能捕获 */
REMOTE_IN_TIMX->CCER  |= 0 << (1 + 4*(chy-1)); /* CC2P=0 先设上升沿捕获 */
REMOTE_IN_TIMX->EGR   |= 1 << 0;               /* 产生更新事件让 PSC 立即生效 */
REMOTE_IN_TIMX->DIER  |= 1 << chy;             /* 开通道2捕获中断 */
REMOTE_IN_TIMX->DIER  |= 1 << 0;               /* 开更新(溢出)中断 */
REMOTE_IN_TIMX->CR1   |= 1 << 0;               /* 启动 TIM5 */

sys_nvic_init(1, 2, REMOTE_IN_TIMX_IRQn, 2);   /* 抢占1/子2/分组2 */
```

要点：`chy=2`（通道2），所以操作的是 `CCMR1` 的第二组、`CCER` 的 CC2E/CC2P 位、`DIER` 的 CC2IE 位。`EGR |= 1` 是软件触发一次更新，让刚写的 PSC 立刻生效而不用等第一次溢出。

### 5.2 中断服务：边沿切换 + 量脉宽 + 判定

```c
void TIM5_IRQHandler(void) {
    if (tsr & 0x01) { /* ...处理 10ms 溢出，做超时/连发计数... */ }

    if (tsr & (1 << chy)) {                 /* 通道2捕获中断 */
        if (RDATA) {                        /* 此刻读到引脚是高 → 刚发生上升沿 */
            REMOTE_IN_TIMX->CCER |= 1 << (1 + 4*(chy-1));  /* 切成下降沿捕获 */
            REMOTE_IN_TIMX->CNT = 0;        /* 计数清零，开始量这段高电平 */
            g_remote_sta |= 0X10;           /* 标记上升沿已捕获 */
        } else {                            /* 下降沿：量到了高电平宽度 */
            dval = REMOTE_IN_TIMX_CCRY;     /* 读 CCR2，即高电平 µs 数 */
            REMOTE_IN_TIMX->CCER &= ~(1 << (1 + 4*(chy-1))); /* 切回上升沿 */

            if (g_remote_sta & 0X80) {      /* 已收到引导码，正在收数据位 */
                if      (dval > 300  && dval < 800)   { g_remote_data >>= 1; /* 0 */ }
                else if (dval > 1400 && dval < 1800)  { g_remote_data >>= 1; g_remote_data |= 0x80000000; /* 1 */ }
                else if (dval > 2000 && dval < 3000)  { g_remote_cnt++; /* 连发一次 */ }
            } else if (dval > 4200 && dval < 4700) {  /* 引导码 4.5ms */
                g_remote_sta |= 1 << 7;     /* 标记收到引导码 */
                g_remote_cnt = 0;           /* 清按键次数 */
            }
        }
    }
    REMOTE_IN_TIMX->SR = 0;                 /* 清所有中断标志 */
}
```

逻辑串起来：**上升沿清零计时 → 下降沿读出宽度 dval → 用 dval 落在哪个区间判断它代表引导码/0/1/重复**。数据位采用"先右移再在最高位放本位"的方式拼装，配合 NEC 的 LSB-first，最终低字节正好是地址码。

### 5.3 remote_scan：校验并取出键值

```c
if (g_remote_sta & (1 << 6)) {                 /* 已采完整一帧 */
    t1 = g_remote_data;                        /* 字节0：地址码 */
    t2 = (g_remote_data >> 8) & 0xff;          /* 字节1：地址反码 */
    if ((t1 == (uint8_t)~t2) && t1 == REMOTE_ID) {  /* 地址与其反码互为取反，且地址=REMOTE_ID */
        t1 = (g_remote_data >> 16) & 0xff;     /* 字节2：命令码 */
        t2 = (g_remote_data >> 24) & 0xff;     /* 字节3：命令反码 */
        if (t1 == (uint8_t)~t2) sta = t1;      /* 命令校验通过，返回键值 */
    }
    if ((sta == 0) || ((g_remote_sta & 0x80) == 0)) { /* 数据错误/已松手 */
        g_remote_sta &= ~(1 << 6);             /* 清"采集完成"标志 */
        g_remote_cnt = 0;                      /* 清按键次数 */
    }
}
return sta;
```

校验规则很简单：**每对字节必须满足"码 = ~反码"**，地址还得等于本遥控器识别码（`REMOTE_ID = 0`）。都通过才认为键值 `sta` 可信。

## 七、实验现象

1. 上电后 LCD 显示 "STM32 / REMOTE TEST / ATOM@ALIENTEK"，以及 KEYVAL/KEYCNT/SYMBOL 三行。
2. 把遥控器**对准板载红外接收头**（距离几米内、角度别太偏），按一下按键：
   - LCD 的 KEYVAL 行显示该键的命令码（十进制，3 位）；
   - KEYCNT 行显示本次按键被"连续计数"的次数（按住不放，重复码会让它累加）；
   - SYMBOL 行显示按键含义（如 POWER、UP、5…）。
3. LED0 周期性闪烁，表示程序运行。
4. 按不同键，键值与文字随之变化；若显示 0/ERROR 或不更新，多为没对准、距离太远或键不在表里。

## 八、注意事项

- **必须对准接收头**：红外是直线传播、怕遮挡、怕强光。接收不到时检查方向、距离、遥控器电池。
- **PA1 必须是上拉输入**：接收头"低有效"，空闲高电平靠上拉维持；配成下拉或推挽会解码全乱（见 `remote_init()`）。
- **引导码丢失**：一次按键若没先收到 4.5ms 引导码（bit7 没置位），后续 0/1 全被忽略——常见于中途被打断或脉宽测量超时，重新完整按一次即可。
- **连发与计数**：遥控器"按住不放"会以约 110ms 间隔重复发码，`g_remote_cnt` 会累加；正常一次短按计数应较小。
- **仅支持 MCU 屏**：本实验依赖 LCD 显示，RGB 屏不支持。
- **串口助手**：必须用 XCOM/SSCOM，避免其它工具拉 DTR/RTS 复位 MCU。
- **官方说明差异**：`readme.txt` 列了 LED1(PD2) 等资源，但 main 流程里实际只用到 LED0 与 LCD，其它为板载通用资源，未参与本实验逻辑。

## 九、总结与延伸

**本实验掌握的要点：**
1. NEC 红外协议：9ms 引导码、1.125ms 逻辑0、2.25ms 逻辑1、2.5ms 重复码的时序含义。
2. 用定时器**输入捕获**量高电平宽度，把"时间"转成"0/1"的解码思想。
3. TIM5 参数：PSC=71→1µs 计数，ARR=10000→10ms 溢出的计算方法。
4. 用状态字节 `g_remote_sta` + 32 位移位寄存器 `g_remote_data` 跨中断拼帧。
5. "码 + 反码"双校验确保解码正确。

**延伸小练习：**
- 往 `main.c` 的 `switch` 里补上你遥控器其它键的键值与文字。
- 把键值同时用 `printf` 通过串口打印，方便用串口助手记录按键。
- 修改判定阈值区间（如把 300~800 收窄），观察误码率变化，体会噪声容限。

**衔接**：理解了"靠脉宽时间解码"，再去看 DS18B20 单总线、其它串口类协议会更容易；本实验的输入捕获技巧也常用于测频、测脉宽等通用场景。
