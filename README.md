# 正点原子 STM32F103 寄存器版实验合集

> 41 套可直接编译运行的 STM32F103 例程，**不用 HAL、不用标准库，全部直接读写寄存器**。
> 每个实验都自带官方 `readme.txt` 与一份中文 `README.md` 精讲文档。

## 一、这个项目是什么

这里是正点原子（ALIENTEK）《STM32 库开发实战指南》**寄存器开发版本**的完整例程工程：

- 覆盖 GPIO、中断、串口、看门狗、定时器、ADC/DAC、DMA、IIC/SPI、触摸屏、红外、
  单总线传感器、内部 FLASH、内存管理、SD 卡、FATFS 文件系统、字库与图形显示、
  DSP 库、手写识别、拼音输入法、串口 IAP、USB、μC/OS-II 实时操作系统，直到最后的综合测试项目。
- 每个实验都是一个**独立完整的 Keil MDK 工程**，互不依赖，可以单独打开、单独编译、单独下载。
- 所有例程按 **正点原子 MiniSTM32 V4 开发板**（主芯片 `STM32F103RC`，Cortex-M3，72MHz）编写。

### 什么叫"寄存器版"

STM32 本身只是一堆可读写的 32 位"控制格子"（寄存器），配置一个外设就是按位把这些格子填成想要的值。
上层库（标准库 `StdPeriph`、HAL 库）帮你把这些填格子的动作封装成了 `GPIO_Init()`、`HAL_GPIO_WritePin()` 这样的函数。

本工程**不做这层封装**，而是自己写：

```c
RCC->APB2ENR |= 1 << 2;              /* 开 GPIOA 时钟：直接置位寄存器第 2 位 */
GPIOA->CRH &= 0x0FFFFFFF;            /* 清掉 PA8 的 4 位配置 */
GPIOA->CRH |= 0x03000000;            /* PA8 配成 50M 通用推挽输出 */
GPIOA->ODR |= 1 << 8;                /* PA8 输出高电平 */
```

好处很直接：**你知道每一行代码到底动了硬件的哪个位置**。学完这一遍再看 HAL 库，
那些函数对你就不再是"黑盒咒语"，而是可以预判行为的工具。这也是本工程最大的学习价值。

## 二、目录结构与约定

```
tk-stm32f103-reg/
├── README.md                     ← 本文件：总览 + 学习路线 + 全实验索引
├── keilkill.bat                  ← 一键清除 Keil 编译中间产物（Windows 批处理）
└── 实验N xxx实验/                 ← 每个实验一套完整工程
    ├── User/                     主程序 main.c（部分实验有 main1.c/main2.c 供切换演示）
    ├── Drivers/
    │   ├── CMSIS/                芯片头文件 stm32f1xx.h、启动文件、系统初始化
    │   ├── SYSTEM/               原子哥自研底层：sys(时钟/GPIO/NVIC)、delay、usart
    │   └── BSP/                  本实验相关板级驱动（LED/KEY/ADC/LCD/…）
    ├── Middlewares/              第三方中间件（USMART/MALLOC/FATFS/GUI/UCOSII/DSP…）
    ├── Projects/MDK-ARM/         Keil 工程文件 atk_f103.uvprojx
    ├── Output/                   已编译好的固件 atk_f103.hex（可直接烧录验证）
    ├── readme.txt                官方实验说明（GBK 编码）：目的/引脚/现象/注意事项
    └── README.md                 ← 本仓库补充的精讲文档（UTF-8，中文）
```

三个约定要提前知道：

1. **源码是 GBK 编码，官方 `readme.txt` 也是 GBK。** 用 VS Code / Qoder 等编辑器打开出现中文乱码时，
   手动切换文件编码为 `GB2312/GBK` 再打开；本工程新增的所有 `README.md` 统一是 UTF-8，正常显示。
2. **8 个实验是"一实验多子工程"结构**：实验 7、8、9、14、16、18、32、35。
   子实验各自有独立 Keil 工程，父目录的 `README.md` 会用小节形式逐个讲完。
3. **每个实验目录都能独立编译**，不需要先编译别的库；换实验就是换一个文件夹打开。

## 三、快速上手（10 分钟跑通实验 1）

1. **装环境**：Keil MDK-ARM 5。工程是用 **ARMCC V5.06 update 7（AC5 编译器）** 建立的
   （`.uvprojx` 里 `<uAC6>0`），用 AC6/clang 打开时可能要把 `Options → Target → ARM Compiler`
   切回 AC5，或按提示调整少量编译选项；另外在 Pack Installer 里装好 `STM32F1xx_DFP` 器件支持包。
2. **接板子**：MiniUSB 线连开发板 `USB_UART` 口给电脑识别出串口（CH340 驱动要先装），或用 ST-Link/J-Link 连 SWD 接口。
3. **开工程**：Keil → `File → Open Project` →
   [`实验1 跑马灯实验/Projects/MDK-ARM/atk_f103.uvprojx`](<实验1 跑马灯实验/Projects/MDK-ARM/atk_f103.uvprojx>)。
4. **编译**：`F7`（Rebuild）。目标器件为 `STM32F103RC`，启动文件 `startup_stm32f103xe.s`。
5. **下载**：`F8`（Download）用 ST-Link/J-Link 烧录；没有调试器时，把 BOOT0 置 1、复位后用飞线/串口 ISP 烧 `Output/atk_f103.hex`，烧完把 BOOT0 改回 0。
6. **看现象**：LED0（PA8）与 LED1（PD2）交替点亮 500ms，就是跑马灯。

配套精讲文档：[实验1 跑马灯实验 README](<实验1 跑马灯实验/README.md>)

> 赶时间想先看效果？每个实验的 `Output/atk_f103.hex` 都是现成固件，直接烧录就能验证现象，
> 再回头读代码，也是一种高效学法。

## 四、学习路线（九个阶段）

按顺序推进即可，每个阶段末尾都有"过关标准"，达标了再往下走，不要跳级。

### 阶段一 · 打地基：GPIO、中断、串口（实验 1~6，约 1 周）

学会"配置一个外设"的通用套路：**开时钟 → 配模式 → 读写数据 → （需要时）配中断**。
实验 4 的串口是全工程最重要的辅助工具，后面绝大多数实验靠它打印数据，务必练熟。

- 实验 1 跑马灯 → GPIO 输出（CRL/CRH 的 CNF+MODE 位）
- 实验 2 按键输入 → GPIO 输入 + 软件消抖
- 实验 3 外部中断 → EXTI + AFIO 线路映射 + NVIC 优先级分组
- 实验 4 串口 → USART 寄存器、BRR 波特率、收发标志位、中断接收
- 实验 5/6 看门狗 → IWDG（LSI 独立时钟）与 WWDG（PCLK 分频 + 窗口值），理解"程序跑飞如何自救"

**过关标准**：能不看资料手写 LED 初始化、按键读取、串口发送一个字符；能说清 NVIC 的抢占/子优先级分组。

### 阶段二 · 定时器：单片机的"节拍器"（实验 7~9，约 1~2 周）

定时器是后续 PWM、输入捕获、ADC 触发、RTOS 心跳的共同基础，是全工程最值钱的一章。

- 实验 7 基本定时器（TIM6）→ 溢出中断、PSC/ARR 与溢出时间计算
- 实验 8 通用定时器（TIM2/3/4）→ 中断、PWM 输出、输入捕获测频率占空比、外部脉冲计数
- 实验 9 高级定时器（9-1/9-3 用 TIM1，9-2/9-4 用 TIM8）→ 指定个数 PWM / 输出比较 / 互补输出 + 死区 / PWM 输入模式

**过关标准**：给你任意定时需求能口算出 PSC 与 ARR；理解 PWM 占空比 = CCR/ARR 的由来；
明白为什么要死区。

### 阶段三 · 显示与人机交互（实验 10~12，约 1 周）

- 实验 10 OLED → 软件模拟 IIC 驱动 SSD1306，理解显存与页寻址
- 实验 11 TFTLCD（MCU 屏）→ 并口时序、RGB565、画点/线/圆/字符，做界面全靠它
- 实验 12 USMART 调试 → 用串口命令行直接调用函数，是调试大工程的利器

**过关标准**：能独立在屏上显示任意字符串和一个数字；会用 USMART 在线调用自己的函数。

### 阶段四 · 时钟、功耗与模拟外设（实验 13~18，约 2 周）

- 实验 13 RTC → 备份域访问、LSE 晶振、1Hz 预分频、日历与时间戳换算（掉电能否走时取决于 VBAT）
- 实验 14 低功耗 → PVD 电压监控 + 睡眠/停止/待机三档模式，理解唤醒源与重新配置时钟
- 实验 15 DMA → 不经过 CPU 的数据搬运，省 CPU 的关键
- 实验 16 ADC → 单通道 / DMA / 多通道扫描 / 过采样提升分辨率（共 4 个子实验）
- 实验 17 内部温度传感器 → ADC 通道 16 + 温度换算公式
- 实验 18 DAC → 直接输出、三角波、DMA + 定时器触发输出正弦波（共 3 个子实验）

**过关标准**：知道 ADC 采样时间怎么算、DMA 配置四要素、DAC 波形频率由谁决定；
能说出三种低功耗模式谁保持 RAM、谁需要重新配时钟。

### 阶段五 · 通信协议与传感器（实验 19~25，约 2~3 周）

工程里最"实用"的一章：总线协议一旦理解，任何同类芯片都不再陌生。

- 实验 19 IIC → GPIO 软件模拟 IIC，驱动板载 24C02 EEPROM（含页写与擦写寿命）
- 实验 20 SPI → SPI1 寄存器、CPOL/CPHA 四种模式、驱动 SPI FLASH（读写必须先擦除）
- 实验 21 触摸屏 → 电阻屏（XPT2046/TSC2046 等，走 SPI）与电容屏（FT5206/GT9147 等，走 IIC）
  自动识别 + 坐标读取与校准
- 实验 22 红外遥控 → NEC 协议解码，用定时器输入捕获（TIM5 CH2 / PA1）量脉宽
- 实验 23 DS18B20 → 单总线时序与微秒级延时精度
- 实验 24 DHT11 → 单总线温湿度 40 位数据与校验和
- 实验 25 无线通信 → NRF24L01 + SPI，收发配对（**需要两块开发板**）

**过关标准**：手撕 IIC/SPI 时序图；明白为什么单总线对延时精度极其敏感；能独立读任何芯片的时序手册。

### 阶段六 · 存储与内存管理（实验 26~29，约 1~2 周）

- 实验 26 FLASH 模拟 EEPROM → 内部 FLASH 解锁/擦页/编程，掉电保存的经典做法
- 实验 27 内存管理 → 自己实现 `malloc`：单池 SRAM 管理器、内存对齐、空闲块合并与碎片处理
- 实验 28 SD 卡 → 走 SPI 总线驱动 TF 卡：初始化命令序列（CMD0/CMD8/ACMD41/CMD16/CMD9）与块读写
- 实验 29 FATFS → 挂接文件系统，实现文件的创建/读写/删除（**需自备 TF 卡**）

**过关标准**：理解 FLASH"只能按页擦、只能 1→0"的本质；会用 FATFS 的 `f_open/f_read/f_write`。

### 阶段七 · 图形、字库与算法应用（实验 30~34，约 2~3 周）

把前面所有驱动组合成"能用的产品功能"。

- 实验 30 汉字显示 → 点阵字库、GB2312 内码 → 字模偏移计算
- 实验 31 图片显示 → BMP 文件解析 + 从 TF 卡读图显示（简易数码相框）
- 实验 32 DSP 测试 → CMSIS-DSP 基本数学函数与 FFT（含 2 个子实验，需实测耗时对比）
- 实验 33 手写识别 → 触摸屏采集笔迹轨迹，交给正点原子闭源识别库（ATKNCR）判定数字/字符
- 实验 34 T9 拼音输入法 → 拼音引擎 `pyinput.c` + SPI FLASH 里的中文库，触屏选字完成输入

**过关标准**：会做字库、能读懂图片文件格式；知道 DSP 库为何比浮点运算快（硬件 MAC）。

### 阶段八 · 系统级能力：IAP 与 USB（实验 35~37，约 2 周）

- 实验 35 串口 IAP → Bootloader + FLASH_APP + SRAM_APP 三个工程，讲透 FLASH 分区、
  中断向量表偏移、跳转流程（**升级功能的全部原理都在这里面**）
- 实验 36 USB 读卡器 → USB SLAVE + Bulk-Only 传输，把 SPI FLASH 与 TF 卡做成双 LUN U 盘
- 实验 37 USB 虚拟串口 → CDC 类，插上 USB 就是一个 COM 口

**过关标准**：能说清"从 Bootloader 跳到 APP 要做的三件事"；理解 USB 枚举过程。

### 阶段九 · 实时操作系统与综合实战（实验 38~41，约 3~4 周）

- 实验 38 μC/OS-II 任务调度 → 任务、优先级、上下文切换（PendSV/SysTick）
- 实验 39 μC/OS-II 信号量和邮箱 → 任务同步与通信
- 实验 40 μC/OS-II 消息队列、信号量集和软件定时器 → 更复杂的资源管理
- 实验 41 综合测试 → 运行在 μC/OS-II（`SYS_SUPPORT_OS=1`，4 个任务、1ms 节拍）上的多功能终端：
  电子图书 / 数码相框 / 时钟 / 记事本 / 运行器 / 手写画笔 / 科学计算器 / 电压表 / USB / 网络（CH395Q）/ 无线传书（NRF24L01）。
  源码里还留有 camera、nes、audio 等头文件引用，但它们**没有**加进 Keil 编译列表，属于未完成的功能骨架。
  全工程大汇总，也是最像"真产品"的一个项目

**过关标准**：能把裸机 while(1) 项目重构成多任务结构；读得懂综合测试工程的模块划分。

### 时间不够怎么学（精简路线）

只有一周：实验 1→2→3→4→7→8-2(PWM)→10(OLED)。
只关注面试常考：GPIO、中断(3)、串口(4)、定时器(7/8)、DMA(15)、ADC(16)、IIC/SPI(19/20)、RTOS(38)。

## 七、常见问题（先查这里）

**Q1：打开 `readme.txt` / 源码注释全是乱码？**
文件是 GBK 编码。VS Code / Qoder 右下角点编码 → `Reopen with Encoding` → 选 `Chinese (GBK)`。
不要直接保存成 UTF-8，否则 Keil 里中文注释会坏掉。

**Q2：编译报"找不到器件 STM32F103RC"？**
Keil Pack Installer 里安装 `STM32F1xx_DFP` 器件支持包，或在 `Options → Device` 手动选择。

**Q3：串口助手收不到数据 / 一收数据就复位？**
① 波特率必须 115200；② 用 XCOM / SSCOM 等原子哥推荐串口助手，很多开源助手会拉 DTR/RTS 导致板子复位；
③ 板载 CH340 与 USART1 之间要跳线：丝印 `USART1` 排针上 PA9→TXD、PA10→RXD 分别连好；
④ 输入字符串以回车换行结束；
⑤ 中文提示语在源码里是 **GBK 字节**，串口助手要选 GBK/ANSI 编码显示，选 UTF-8 会看到乱码（功能本身不受影响）。

**Q4：下载后 LED 不亮、程序像没跑？**
先看 BOOT0 是否被留在 1（串口 ISP 模式）；再确认供电（4.3/7 寸屏需外接 12V/1A，USB 供不动）；
最后用 `Output/atk_f103.hex` 直接烧一次，排除编译问题。

**Q5：插模块时板子冒烟/芯片发烫？**
一律**先断电**再插模块，对准丝印方向（OLED/LCD 看 VCC 位置；DS18B20 平面朝内靠左；DHT11 网面朝外）。

**Q6：编译产物太多、仓库变大？**
每个实验目录都有 `keilkill.bat`，Windows 下运行即可清理 `*.o/*.d/*.axf/*.map` 等中间文件
（`Output/atk_f103.hex` 之类想留就自己备份）。

**Q7：代码注释里的容量和我的板子对不上？**
本工程目标芯片 `STM32F103RC` 是 256KB FLASH / 48KB SRAM，但部分例程沿用了 F103ZET6/VET6
（512KB/64KB、1MB/96KB）时代的注释，例如实验 27 里"SRAMIN 共 64KB"这类说明。
动到内部 FLASH 页大小、内存池起止地址、IAP 分区地址时，一律以你芯片的实际容量核对宏定义，别照抄注释。

**Q8：为什么有的实验 `readme.txt` 写的引脚和代码不一样？**
官方说明文档在不同开发板之间有部分残留。本工程**以代码宏定义为准**，
例如 LED0 在 `Drivers/BSP/LED/led.h` 里定义为 PA8、LED1 为 PD2；
每份 `README.md` 的"注意事项"都标注了这类差异。

顺带提醒：**源码里的行尾注释也会过时**，可信度排序是
`宏定义/实参 > 寄存器位操作 > 注释 > readme.txt`。
常见例子：注释写"获取通道5"但实参是通道 14；注释写"约 1KHz"按 `dt × 采样点数` 算其实是 100Hz；
注释说"CPOL=0"而位值是 `1 << 1`（CPOL=1）。做实验时自己动手算一遍，别照抄注释。

## 八、代码里已知的几处小坑（核对文档时确认，均未改动源码）

这些是读源码时发现的真实问题。**只记录、不修改**——保持例程与原书一致，方便对照。
知道它们存在，能避免你怀疑自己。

### 会影响行为的

| 实验 | 问题 | 说明与位置 |
| --- | --- | --- |
| 26 | 栈缓冲区越界 | `datatemp` 声明为 `uint8_t datatemp[SIZE]`（SIZE=9），但 `stmflash_read()` 按半字个数写回 9 个半字 = 18 字节，多写 9 字节。见 [实验26/User/main.c:46](<实验26 FLASH模拟EEPROM实验/User/main.c>) 的声明与同文件第 76 行的读取调用 |
| 32-2 | 屏上耗时偏大 100 倍 | FFT 计时实测 1MHz 计数，屏显用 `time / 10` 却标 `ms`；串口打印用 `time / 1000` 才是正确的毫秒值 |
| 21 | 电容屏也会提示校准 | `if (tp_dev.touchtype != 0XFF)` 的行尾注释写"电阻屏才显示"，但电阻屏取 0、电容屏取 0x80 以上，两种屏条件都成立 |
| 9-1 | 脉冲数是 256 整数倍时会丢最后一批 | 中断里先判 `g_npwm_remain > 256`，再判 `g_npwm_remain % 256`；当剩余正好等于 256 时两个分支都不成立，那 256 个脉冲不会输出。见 [实验9-1/Drivers/BSP/TIMER/atim.c:45](<实验9 高级定时器实验/实验9-1 高级定时器输出指定个数PWM实验/Drivers/BSP/TIMER/atim.c>) |
| 16-4 / 18-1 | 采样时间形参没用上 | `adc_channel_set(adcx, ch, stime)` 与 `adc2_channel_set()` 内部把 `stime` 忽略、恒写 7（239.5 周期），所以注释里"1.5 周期提速"不会生效 |
| 18-1 | DAC 引脚配置偏移 | `dac_init()` 用 `1 << (4 + outx)` 计算 GPIO 配置位偏移，`outx=1`（通道 1 / PA4）时实际写到 PA5 的配置位上 |
| 24 | 采样过快 | 主循环 100ms 轮询 DHT11，而 DHT11 要求两次采样的间隔不小于 1s，读到的数值可能不更新或校验失败 |

### 只是注释/文档误导（代码本身按注释相反的值运行）

| 实验 | 注释写的 | 代码实际 |
| --- | --- | --- |
| 20 / 28 | `CPOL=0` | `tempreg \|= 1 << 1` 置的是 CPOL=1，即 SPI 模式 3 |
| 25 | `spi1_set_speed()` 按 PCLK1=36MHz 换算档位 | SPI1 挂在 APB2（72MHz），`SPI_SPEED_32` 实际约 2.25MHz，不是注释的 7.5MHz |
| 16-1 | "获取通道5的转换值" | 实参是通道 14（PC4） |
| 18-2 / 18-3 | "约1Khz" | 按 `dt × 采样点数` 实算是 100Hz（18-2）/ 3kHz（18-3 KEY0） |
| 35 | `iap.h` 注释保留 36KB 分区、APP 注释"偏移 0X9000" | FLASH_APP 实际链接在 `0x08010000`（64KB），向量表偏移实参 `0x10000` |
| 36 | `usbd_storage.c` 注释 LUN0=SD / LUN1=FLASH | 实现相反：LUN0 是 SPI FLASH、LUN1 是 SD 卡；屏上还硬编码 "SPI FLASH Size:7.25MB"，而 USB 暴露的是 12MB |

## 九、学习建议

1. **一定要手敲。** 看懂 ≠ 会写。寄存器版的收获全在"自己填寄存器"这一步。
2. **对照手册读代码。** 打开 STM32F103 中文参考手册（RM0008）与数据手册，
   文档里提到的每个寄存器都去手册查一遍位定义，这是补底层最快的事。
3. **改参数才有感觉。** 把 `sys_stm32_clock_init(9)` 改成别的倍数值、把 PWM 的 ARR 改小一倍、
   把串口波特率改成 9600，先猜现象再验证。
4. **每做完一组，做一次"最小整合"练习。** 例如做完 ADC + DMA + 串口，就把采集值实时打印出来。
5. **卡住先看现象链。** 时钟使能了吗 → 引脚/复用对吗 → 中断使能了吗（外设级 + NVIC 级两处）→
   优先级分组合理吗 → 是不是 GBK/引脚/跳线问题。寄存器版排错全靠这条链。
