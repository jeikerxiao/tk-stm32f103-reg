# 实验6 窗口看门狗实验

> 一句话概括：窗口看门狗（WWDG）要求你在"不早不晚"的一小段窗口里喂狗，并且给你一次"下溢前的抢救中断"——本实验就是靠这个中断自动喂狗，同时让绿灯有节奏地闪烁。

## 一、实验简介

- **实验目的**（官方 `readme.txt`）：学习窗口看门狗（WWDG）的使用。
  通俗讲：它比独立看门狗多了两个本事——① 有一个"允许喂狗的时间窗口"，喂太早也不行；
  ② 计数器快下溢时会先产生一次**提前唤醒中断**，让你在被复位前有机会抢救（本实验就在这里喂狗）。
- **在学习路线中的位置**：前置是「实验5 独立看门狗」；本实验在其基础上讲"窗口"和"下溢中断"。
  它还需要一点中断知识，若已做过按键中断实验会更顺。
- **开发板与芯片**：正点原子 MiniSTM32 V4，主芯片 STM32F103RC。**寄存器版**，直接操作 `WWDG->CR/CFR/SR`。

> 小概念：看门狗 = 一个不断倒数的计数器，到 0 就复位芯片；"喂狗" = 把计数器重新装满，让它别数到 0。

## 二、实验原理

### 2.1 WWDG 与 IWDG 的区别

| 对比项 | IWDG（实验5） | WWDG（本实验） |
| --- | --- | --- |
| 时钟源 | 内部 LSI（约 40kHz，独立） | **APB1 总线时钟 PCLK1**（本工程 36MHz） |
| 喂狗时机 | 只要别超时，随时能喂 | 只能在**窗口内**喂，喂太早反而复位 |
| 下溢前提示 | 无 | 有**提前唤醒中断 EWI** |
| 能否关闭 | 启动后不可关 | 启动后也不可关（WDGA 位只能复位清） |

### 2.2 递减计数 + 窗口值：为什么要"喂得刚好"

WWDG 的核心是一个 7 位递减计数器 `T[6:0]`：从某个初值（本工程 0x7F）往 0 减。规则是：

1. 当计数器减到 **0x3F**（即再减一步就下溢）时，如果没被喂 → 产生复位。所以 `0x40` 是"最后一格"。
2. 想喂狗（重设计数器值），**必须等到计数器的值已经 ≤ 窗口值 W** 时才允许写。
3. 如果计数器还 **> W**（说明离上次喂狗时间太短）你就喂 → 视为"喂得太早" → **立即复位**。

因此合法喂狗区间是一个"窗口"：`0x40 ≤ 计数器 ≤ W`。本实验 `W = 0x5F`，所以只有当计数器落在 `0x40~0x5F` 之间时喂狗才安全。这就是"窗口看门狗"名字的由来。

### 2.3 为什么喂狗要放在"下溢中断"里做

如果让主循环主动喂，你必须算准时间"刚好落在窗口里"，很难且不稳。WWDG 提供了一条捷径：

- 当计数器递减到 `0x40` 时，硬件把状态寄存器 `WWDG->SR` 的 **EWIF（bit0，提前唤醒中断标志）** 置 1；
- 若使能了 `WWDG->CFR` 的 **EWIE（bit9）**，就触发一次 **WWDG 中断**；
- 此刻正好是"下溢前的最后一刻"，也就是**窗口内最保险的一点**。

所以本实验把喂狗动作写在中断服务函数里：中断一来（计数器到 0x40），立刻把计数器重设回 0x7F，
就不会真的下溢复位。**一句话**：借"提前唤醒中断"这个恰好落在窗口里的时刻来喂狗，既不会太早也不会来不及。

### 2.4 关键寄存器与代码里的写法

WWDG 只有 3 个寄存器（结构体见 [stm32f103xe.h](Drivers/CMSIS/Device/ST/STM32F1xx/Include/stm32f103xe.h)）：

| 寄存器 | 偏移 | 关键位 | 本实验填的值 |
| --- | --- | --- | --- |
| `WWDG->CR`  | 0x00 | bit7 `WDGA` 使能位；bit[6:0] `T[6:0]` 计数器 | 计数器初值 0x7F；bit7 置 1 开启 |
| `WWDG->CFR` | 0x04 | bit[6:0] `W[6:0]` 窗口值；bit[8:7] `WDGTB` 分频；bit9 `EWIE` 提前唤醒中断使能 | W=0x5F，WDGTB=3，EWIE=1 |
| `WWDG->SR`  | 0x08 | bit0 `EWIF` 提前唤醒中断标志 | 中断里写 0 清除 |

时钟使能：`RCC->APB1ENR |= 1 << 11;`（WWDGEN，bit11）。WWDG 挂在 APB1 上。

### 2.5 溢出/中断周期计算（代入本工程数值）

喂狗/中断的时间间隔由"计数器从初值减到 0x40 所需的时钟数"决定：

```text
计数器要走的格数 = tr - 0x3F        （tr 是初值，减到 0x3F 触发）
WWDG 时钟       Fwwdg = PCLK1 / (4096 * 2^fprer)
溢出时间 Tout    = 4096 * 2^fprer * (tr - 0x3F) / PCLK1
```

本工程 `wwdg_init(0x7F, 0x5F, 3)`，即 tr=0x7F、fprer=3、PCLK1=36MHz：

- 格数 = 0x7F - 0x3F = 0x40 = **64**
- 分频 = 4096 * 2^3 = 4096 * 8 = **32768**
- Tout = 32768 * 64 / 36,000,000 ≈ **0.05825 s ≈ 58.25 ms**

即每约 58ms 产生一次提前唤醒中断，喂一次狗、翻一次绿灯。这与 `wdg.c` 注释里"58.25ms"完全一致。

2. `LED0(0)`：点亮红灯。
3. `delay_ms(300)`：让红灯亮 300ms，"看得见"。

## 五、核心代码解析

### 5.1 初始化并启动 WWDG —— `wwdg_init`

摘自 [Drivers/BSP/WDG/wdg.c](Drivers/BSP/WDG/wdg.c)（下面即为文件中的原始顺序，未作改写）：

```c
/* 保存WWDG计数器的设置值,默认为最大. */
uint8_t g_wwdg_cnt = 0x7f;

void wwdg_init(uint8_t tr, uint8_t wr, uint8_t fprer)
{
    RCC->APB1ENR |= 1 << 11;        /* 使能wwdg时钟 */
    g_wwdg_cnt = tr & g_wwdg_cnt;   /* 初始化WWDG_CNT. */
    WWDG->CFR |= fprer << 7;        /* PCLK1/4096再除2^fprer */
    WWDG->CFR &= 0XFF80;
    WWDG->CFR |= wr;                /* 设定窗口值 */
    WWDG->CR |= g_wwdg_cnt;         /* 设定计数器值 */
    WWDG->CR |= 1 << 7;             /* 开启看门狗 */
    sys_nvic_init(2, 3, WWDG_IRQn, 2); /* 抢占2，子优先级3，组2 */
    WWDG->SR = 0X00;                /* 清除提前唤醒中断标志位 */
    WWDG->CFR |= 1 << 9;            /* 使能提前唤醒中断 */
}
```

逐句解释：

1. `g_wwdg_cnt`：一个全局变量，保存喂狗时要回写的计数器初值，默认 0x7F（最大），供中断里复用。
2. `RCC->APB1ENR |= 1<<11`：先开 WWDG 外设时钟，否则寄存器写不进去。
3. `g_wwdg_cnt = tr & g_wwdg_cnt`：把用户传入的计数初值 0x7F 与掩码保留到低 7 位存好。
4. `CFR |= fprer<<7`：`WDGTB[1:0]`（bit[8:7]）设分频，fprer=3 → 除以 2^3=8。
5. `CFR &= 0xFF80` 再 `CFR |= wr`：先清窗口字段低 7 位，再写入窗口值 0x5F。
6. `CR |= g_wwdg_cnt`：把计数器初值 0x7F 写入 `T[6:0]`。
7. `CR |= 1<<7`：置 `WDGA`，**启动看门狗**（置 1 后只能靠复位清零，跑不掉）。
8. `sys_nvic_init(2,3,WWDG_IRQn,2)`：NVIC 里使能 WWDG 中断，抢占优先级 2、子优先级 3、分组 2。
9. `SR = 0x00` + `CFR |= 1<<9`：清 `EWIF` 标志并使能 `EWIE`，打开提前唤醒中断，喂狗从此交给中断。

### 5.2 重设计数器（喂狗动作） —— `wwdg_set_counter`

```c
void wwdg_set_counter(uint8_t cnt)
{
    WWDG->CR = (cnt & 0x7F);   /* 重设置7位计数器 */
}
```

把 `T[6:0]` 重新装回 `g_wwdg_cnt`（0x7F），倒数重新开始。这里整字节写 `CR` 也没关系：`WDGA`(bit7) 一旦被硬件锁定不会因写 0 而清零，只有复位才能清。

### 5.3 中断服务函数（喂狗真正发生的地方）

```c
void WWDG_IRQHandler(void)
{  
    if (WWDG->SR & 0X01)               /* 先判断是否发生了WWDG提前唤醒中断 */
    {
        WWDG->SR = 0X00;               /* 清除提前唤醒中断标志位 */
        wwdg_set_counter(g_wwdg_cnt);   /* 重设窗口看门狗的值! */
        LED1_TOGGLE();                  /* 绿灯闪烁 */
    }
}
```

- `if (WWDG->SR & 0x01)`：确认是 EWIF（提前唤醒）进来的。
- `WWDG->SR = 0x00`：**必须清标志**，否则中断会反复触发。
- `wwdg_set_counter(g_wwdg_cnt)`：**这就是喂狗**——在计数器刚降到 0x40、还来得及的最后一刻装满它。
- `LED1_TOGGLE()`：翻转绿灯，于是我们看到 LED1 以约 58ms 的节奏一闪一闪，间接证明"中断在正常喂狗"。

## 七、实验现象

对照官方"实验现象"，实际会看到：

1. 上电后 **LED0（红灯）先亮约 300ms**（`LED0(0)` + `delay_ms(300)`），随后主循环 `LED0(1)` 把红灯关掉——这就是"只在刚启动时闪一下"。
2. WWDG 启动后，每约 58ms 进入一次提前唤醒中断，中断里 `LED1_TOGGLE()` 翻转绿灯。
3. 因此 **LED1（绿灯）持续、均匀地闪烁**（约每 58ms 翻转一次），而 **LED0 保持熄灭**（除非你把狗喂失败/喂太早才会复位，复位瞬间红灯才会又闪一下）。

## 八、注意事项

- **只能在窗口内喂狗**：喂太早（计数器值 > 0x5F）同样触发复位。本例把喂狗放进提前唤醒中断，恰好落在窗口点 0x40，避免踩坑。
- **WDGA 启动后关不掉**：`WWDG->CR` bit7 只能由复位清除；调试时如需暂停，只能复位后重配。
- **一定要清 `SR` 的 EWIF**：中断里若忘记 `WWDG->SR = 0x00`，会一直重复进中断。
- **PCLK1 决定精度**：WWDG 用 APB1 时钟（36MHz），改主频/分频会改变 58ms 这个节奏；IWDG 则用独立 LSI 不受影响。
- **代码与官方说明不一致之处**：官方 `readme.txt` 现象里写"在中断里面，喂狗，并执行 **LED0** 的翻转操作……可以看到 **LED1** 不停的闪烁"，前后自相矛盾。
  **以代码为准**：[wdg.c](Drivers/BSP/WDG/wdg.c) 中断里实际翻转的是 `LED1_TOGGLE()`，所以真正持续闪烁的是 **LED1（绿灯）**，LED0 只是开机闪一下。README 已按代码描述。
- **源码为 GBK 编码**：请正确选择编码打开，避免注释乱码。

## 九、总结与延伸

**本实验要点：**

1. WWDG 用 APB1 时钟（36MHz），带"窗口"限制：太早喂、太晚喂都会复位。
2. 提前唤醒中断（`CFR.EWIE`/`SR.EWIF`）在计数器降到 0x40 时触发，是最保险喂狗点——本例就在这里喂狗。
3. `Tout = 4096 * 2^fprer * (tr-0x3F) / PCLK1`，本工程代入 ≈ 58.25ms。
4. 三个寄存器 `CR/CFR/SR` 各司其职：计数/使能、窗口/分频/中断使能、状态标志。

**延伸小练习：**

1. 把窗口值 `wr` 从 `0x5F` 改小（如 `0x4F`），合法喂狗窗口变窄，思考对喂狗时刻的影响。
2. 把 `fprer` 从 3 改成 1（分频变小），重算 Tout（应约 58.25/4 ≈ 14.6ms），观察绿灯闪得更快。
3. 在中断里加一句读 `RCC->CSR` 的 `RCC_CSR_WWDGRSTF`（bit30），配合 `RCC_CSR_RMVF` 清标志，判断某次重启是否由 WWDG 复位引起。

**衔接**：IWDG（实验5）+ WWDG（本实验）合起来就是 STM32 的两道"看门狗保险"。
